
**Cross-Region Replication:** It means when we upload data to S3, AWS duplicates data on its own in the background in another S3.

**DataSync:** When we have on-premises data center. We want that our data should be stored in both places. In AWS storage and also in our data center.


**S3 Event Notification:** When we create or delete object in S3, Amazon S3 event notifications ek waqt mein sirf ek single destination (ya ek SQS, ya ek SNS, ya ek Lambda) par direct event bhej sakta hai. Aap S3 se multi-destination direct publish nahi kar sakte.


**S3 Transfer Acceleration:** If we have long distance and want to upload large data to S3, we use S3 Transfer Acceleration. We upload data in multiple parts. AWS stores the data in its Edge Locations and then move to S3.




Think:

> **Versioning = keep previous copies**
> **MFA Delete = extra authentication before permanently deleting versions**

### Exam shortcut 🧠

**Accidental S3 deletion → Versioning**

**Need stronger protection against permanent deletion → MFA Delete**

And don't confuse this with:

* **Signed URL** → controlled access
* **S3 storage classes** → cost/storage optimization
* **IAM policies** → permissions/access control

### **Real-Life Misaal 🚗💨**

Maan lein aap ke paas **100 Terabytes (TB)** ka video data ya autonomous vehicle testing data hai jo aap ko S3 bucket mein upload karna hai:

2. **Physical Entry:** Aap apne authorized bande aur ID card ke sath unki secure facility/bay mein jate hain.
3. **Plug & Transfer:** Aap apna device unke **dual 100Gbps high-speed fiber lines** ke sath connect karte hain aur data direct Amazon S3 ya EFS mein bhej dete hain.
4. **Done:** Data transfer hote hi aap apna hardware le kar wapas aa jate hain.

For the common **on-premises → AWS DataSync** scenario, you deploy a **DataSync agent** in your on-premises environment.

Think of it like this:

```text
Your On-Premises Server / NAS
             ↓
      DataSync Agent
             ↓
        AWS DataSync
             ↓
        Amazon S3
```

### Why the agent?

The **DataSync service is in AWS**, but your data is sitting on-premises. The agent provides the connection/transfer capability between your on-premises storage and DataSync.

For example:

> You have **50 TB of files on an on-premises NAS** and want to transfer them to S3.

You would generally:

1. Deploy **DataSync Agent** on-premises.
2. Configure your on-premises storage location.
3. Configure the AWS destination, e.g. S3.
4. Create a DataSync task.
5. DataSync transfers/synchronizes the files.

### 🧠 Exam memory

**DataSync:**

> **Agent → transfer/sync → AWS storage**

**Storage Gateway:**

> **Gateway → on-premises application uses AWS-backed storage**

And one important point: **DataSync is not the same as Direct Connect.** DataSync is the **data-transfer service**; Direct Connect is the **network connection** that can provide dedicated connectivity.
